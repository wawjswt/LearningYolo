# AlexNet 逐层数据流与张量尺寸修正

## 原有问题

- 正文把224→55→27等尺寸压在一段话中，没有在每一步同时标注N、C、H、W。
- 旧结构图采用2012原论文的通道数，正文又介绍Torchvision版本，读者需要自己拼接两套结构。
- 图上把Conv3–5合并，省略ReLU、池化等操作，无法逐层追踪。
- 未解释多输入通道如何汇成一个输出通道、展平为什么保留批次轴、全连接如何从9216走到1000。

## 已实施的修改

1. 主线固定为Torchvision AlexNet，224输入、groups=1、dilation=1，五个卷积通道数为64、192、384、256、256。原论文放在明确标注的版本对照中。
2. 按输入、Conv1与池化、Conv2与池化、Conv3/4/5、最后池化、自适应平均池化、展平、分类器的顺序重写正文，解释所有符号和数值变化。
3. 数据流交互列出输入、22个网络操作及模型外可选Softmax。每个操作显示输入和输出shape、配置、尺寸计算、每张图元素数、整批元素数、权重形状和含偏置参数数。
4. 提供上一操作/下一操作、直接选层、批次1/2/4、高宽224/256和恢复默认。完整表格与PyTorch打印代码同步更新。
5. Conv1提供单窗口手算图解：三个11×11通道分别填1/2/3，363个权重全为1，偏置1，结果121+242+363+1=727。明确这是教学输入与权重，不是训练模型输出。
6. 解释224下6→6的自适应池化为恒等、256下7→6需要求平均；解释Dropout的训练/评估差异，展平不混合批次，logits后不接ReLU，交叉熵接收原始分数。
7. 历史技巧与比赛成绩后置。修正旧重叠池化演示：5×5输入、3×3窗口、步幅2，四个起点为(0,0)/(0,2)/(2,0)/(2,2)。修正ReLU在0点的导数表述。

## 统一尺寸约定

| 操作 | 单张图片的输出shape |
| --- | --- |
| 输入 | [1,3,224,224] |
| Conv1 / ReLU1 | [1,64,55,55] |
| MaxPool1 | [1,64,27,27] |
| Conv2 / ReLU2 | [1,192,27,27] |
| MaxPool2 | [1,192,13,13] |
| Conv3 / ReLU3 | [1,384,13,13] |
| Conv4 / ReLU4 | [1,256,13,13] |
| Conv5 / ReLU5 | [1,256,13,13] |
| MaxPool3 / AdaptiveAvgPool | [1,256,6,6] |
| Flatten / Dropout1 | [1,9216] |
| FC1 / ReLU6 / Dropout2 | [1,4096] |
| FC2 / ReLU7 | [1,4096] |
| FC3 logits / 模型外可选Softmax | [1,1000] |

上表合并同形状的相邻操作便于概览；网页完整表和代码逐个列出这些操作。

## 验证

- 新增回归检查在修改前因缺少完整层追踪而失败，修改后通过。
- 使用本机已有AI环境（torch 2.1.0、torchvision 0.16.0），不安装依赖、不下载权重。实际执行网页生成的PyTorch代码，覆盖N=1/2/4与输入224/256共六组前向。
- 每组核对全部操作的输入/输出形状、所有可训练层的权重形状与参数数，总参数61,100,840；分步前向与model(image_batch)结果相同。
- 实际运行Conv1单窗口727算例；实际运行7×7→6×6自适应池化并验证首个区域对[0,1;7,8]求平均为4。
- 运行基础课程与BatchNorm回归检查，共32项通过；全部课程渲染检查通过。
- 本地浏览器确认N=2/高宽256时7×7→6×6、展平后[2,9216]、恢复224主线、完整表、代码更新、公式显示；无控制台错误。

## 来源与边界
