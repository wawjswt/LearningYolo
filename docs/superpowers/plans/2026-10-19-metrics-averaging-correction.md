# 检测指标口径修正实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement task-by-task in the current session. 不使用子代理。以下步骤用复选框记录进度。

**Goal:** 让合成教学数据和导入 YOLOv5 数据的指标名称、计算口径、公式、计数说明及曲线注释一致。

**Architecture:** 沿用现有静态网站和两个数据入口。“全部类别”统一显示类别宏平均，单类别使用该类别的普通 P/R/F1。保留各自的 AP 计算协议，通过一处小型公共计数聚合函数复用工作点计算；界面将总计数与宏平均指标明确解释。

**Tech Stack:** 原生 JavaScript、HTML、现有 SVG 图表、Node.js 内置 assert/vm 验证脚本。

**Spec:** 本文件中的“修正约定”，依据本轮知识准确性审阅及用户后续“实施”的确认。指标实现与说明已按该约定修正，并进入站点验收和发布。

## 修正约定

- 全部类别：先分别计算每类 P、R、F1，再对参与评估的类别取算术平均；默认合成数据和导入数据采用同一口径。
- 单类别：P=TP/(TP+FP)，R=TP/(TP+FN)，F1=2PR/(P+R)。无预测时 P 显示 0，R/F1 按现有零值约定处理。
- 总 TP、FP、FN 保留，标明“各类别数量合计”；说明它们不能直接代入公式得到类别宏平均。
- 宏平均 F1=各类别 F1 的平均值，不从宏平均 P、R 再算调和平均。
- 有真实目标但没有预测的类别仍参与宏平均，以 0 计；评估类别集合保持由现有有效标注类别定义。
- AP/mAP、匹配标记、导出 JSON 格式及历史 swim_v9 记录维持现有评估协议。
- PR 插值包络与当前置信度下的离散工作点明确区分；全部类别的包络按相同 Recall 平均，不暗示它是共同置信度的工作点轨迹。
- F1 曲线显示类别 F1 的平均值；当前工作点使用精确计数。保留 YOLOv5 绘图插值时明确标注，避免将插值读数当成精确计数结果。

## Global Constraints

- 不使用子代理；后续实施在当前会话完成。
- 复用现有模块、样式和 verify.cjs，不新增运行时依赖，不拆分整个实验室模块。
- 教学正文独立可读，不使用“视频里提到”等依赖来源的表述。
- 只修正已确认的指标口径问题及直接相关解释。
- 按当前站点托管流程发布修正；不向项目 GitHub `origin` 提交或推送，除非用户另行提出。

## Review Focus

- 类别样本量不均衡时，宏平均与汇总计数的微平均明显不同，两个入口须输出一致口径。
- 各类 P/R 差异很大时，宏平均 F1 不等于宏平均 P/R 的调和平均。
- 有标注但无预测的类别仍计入平均；高置信度阈值下不得出现 NaN。
- 合成、导入、单类别、全部类别及恢复合成样例之间切换时，标签和公式及时同步。
- PR 包络、当前工作点和 F1 插值曲线的说明与实际绘图方法一致；AP/mAP 不因工作点聚合改变。
