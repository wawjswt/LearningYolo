# YOLO 课程讲解与交互改进计划

> **执行方式：** 后续使用 `superpowers:executing-plans`，由当前助手逐项实施、自查；遵守用户既定要求，不使用子代理。用下方复选框记录进度。

**目标：** 让初学者能够沿着一张图片的处理过程，说明 YOLOv5 为什么这样组织网络，手算关键张量尺寸和框坐标，读懂检测头输出，并有依据地训练、改模型和排错。

**实现方式：** 沿现有五阶段、24 门 YOLO 课程改写。复用已有逐层浏览器、标签变换、Neck 路径、Detect、样本分配、损失和 NMS 交互，补齐它们之间的讲解和数值对应；统一基础算例，分开基础阅读、项目操作和结构改造。

**技术栈：** 现有静态 HTML、CSS、JavaScript、SVG、KaTeX；随课核对代码使用 PyTorch 和已有 YOLOv5 源码。不增加前端依赖，不引入在线训练服务。

**需求依据：** 用户本轮要求“强化、丰富、改进 yolo 部分的讲解，要让人易懂、清楚明白，便于学习”，以及 [AGENTS.md](../../../AGENTS.md) 的教学约定；具体范围与验收见本文第 1、5、10 节。

**状态：** 第一、二批已实施逐层账本、两类检测头主线，并将一张标注贯穿匹配、损失、参数更新、验证、推理和导出；逐课完整审读及模型改造内容仍待后续批次处理。实际验证和保留事项见 [实施记录](../../reviews/2026-10-27-YOLO教学改进实施记录.md)。

**审查基线：** 2026-10-27，网站 v126；源码 `4ad4bc85fc2a753d8f672b8c4442e59d00f88dbe`。全站 96 课，其中 YOLO 24 课、85 节。检查依据为按 `dist/index.html` 实际加载顺序生成的最终课程对象、重点小节正文、交互实现和本地 YOLOv5 源码；本次未进行网站逐页浏览器视觉验收或模型运行。

## 1. 本轮要达到什么程度

学习者读完基础主线，应能完成下面这些具体动作：

1. 用一张图说明分类与检测的区别，分清真实框、参考框、候选预测、最终检测结果。
2. 从图片的高、宽、颜色通道理解 `[B,C,H,W]`，沿网络核算关键层的输入、操作、输出；知道为什么某些早期输出要保留下来。
3. 解释 C3、SPPF、FPN/PAN 和 Detect 各自处理什么问题，并指出它们在同一张结构图中的位置。
4. 读懂两类检测头的一条候选记录，算出 21 个输出通道、三尺度原始形状和 25,200 条候选的来源。
5. 沿一条标签算到网格位置、匹配索引和局部训练目标，分清三个损失分别监督什么。
6. 将一个预测从输入画布还原到原图，手动完成少量候选的分数筛选、NMS 和评价匹配。
7. 找到第一次训练需要的文件、命令和检查结果；改类别或检测尺度后，知道应该检查哪些输出和代码。

### 全局约束

- 核心对象在每门课正文入口定义：是什么、输入和输出是什么、为什么需要。第一次出现的新词就在附近解释，不能把解释全交给 tooltip 或词典。
- 讲解顺序为具体问题 → 小例子 → 逐步计算 → 公式和代码 → 使用边界。同一计算讲完后再转向下一件事。
- 零基础主线中的公式逐个说明符号、单位和取值。数学公式用现有 KaTeX；API、文件路径和命令使用代码样式。
- 英文缩写首次出现给出全称和中文名；BN、SiLU 等已有基础课的概念，在使用处简短解释并给直达链接，不把整段基础知识复制进模块计算中间。
- 主线采用本网站已有的标准 Anchor-based YOLOv5l 结构；官方固定 v7.0 是对照来源。本地有修改的默认路径、增强、解析或评价行为，逐项指出，不能直接宣称与官方完全相同。
- 基础网络算例统一为输入高 640、宽 640，`B=1`、`nc=2`、P3/P4/P5、每位置 3 个 Anchor；80 类、矩形输入、P2 和解耦头作为有明确条件的对照。
- 不把“候选有 25,200 条”写成“检测到了 25,200 个物体”；不把分数简单解释为已经校准的真实概率；不把更大输入、增加 P2 或解耦头写成必然提升精度。
- 保留 24 门课程及现有稳定小节 ID、旧链接、学习进度、练习关联。优先在现有 85 节内用小标题和折叠组织内容，不为凑数量另开重复课程。
- 图、表、公式、交互和代码使用同一组输入；示意特征、人工预测与实际模型运行结果明确标注。
- 本轮聚焦 YOLO；只在必要处增加基础课直达链接，不借机重写其他课程。

## 3. 固定一条贯穿算例

### 3.1 算例条件

使用一张人工绘制的烟雾/火焰场景示意图，跟踪其中一处火焰。它用于准确演算，不冒充真实检测结果。

- 类别顺序固定：`0=smoke（烟雾）`，`1=fire（火焰）`。
- 原图宽 1000、高 500；火焰框中心 `(530,220)`，宽 50、高 25。
- 模型输入高 640、宽 640；等比缩放比例 `r=0.64`，上下各补 160，左右不补。
- 标准 YOLOv5l 三尺度，`B=1`、`nc=2`。Anchor 表沿用标准配置；不在例子中暗改 AutoAnchor 结果。

选择这组数的原因：它能接上现有分配交互的中心 `(42.4,37.6)` 和目标宽高 `(4,2)`，无需为了统一故事而另造一套分配规则。

### 3.2 必须贯通的中间值

| 环节 | 数值 | 讲解必须说明的对象和单位 |
| --- | --- | --- |
| 原图角点 | `(505,207.5)` 到 `(555,232.5)` | 连续框坐标可以有小数；这不是像素数组的整数索引 |
| 磁盘标签 | `1 0.53 0.44 0.05 0.05` | 类别、原图归一化中心 x/y、原图归一化宽/高 |
| 缩放后的框 | 中心 `(339.2,140.8)`，宽高 `(32,16)` | 相对缩小后的 640×320 图像，尚未补边 |
| 补边后的框 | 中心 `(339.2,300.8)`，宽高 `(32,16)` | 相对模型的 640×640 输入画布 |
| 内存中的目标 | `[0,1,0.53,0.47,0.05,0.025]` | 图片索引、类别、输入画布归一化 xywh；磁盘标签文件没有图片索引 |
| P3 网格坐标 | 中心 `(42.4,37.6)`，宽高 `(4,2)` | 步幅 8；网格列 x、网格行 y，与张量索引次序不同 |
| 跟踪一个通过匹配的 Anchor | 索引 1（从 0 编号的第二组），像素宽高 `(16,30)`，网格宽高 `(2,3.75)`；最大宽高比例为 2 | 这里只跟踪其中一个匹配项，不表示其他 Anchor 或其他尺度没有正样本 |
| 中心格索引 | `(b,a,gj,gi)=(0,1,37,42)` | 最后两项是行、列；局部目标 `[0.4,0.6,4,2]` |
| 邻格示例 | 左邻 `(0,1,37,41)`，局部中心 `(1.4,0.6)`；下邻 `(0,1,38,42)`，局部中心 `(0.4,-0.4)` | 这些局部中心可以超出 0～1；按当前源码条件产生，不是任意复制到周围 8 格 |
| 理想位置预测 | 解码后的 xywh 为 `(339.2,300.8,32,16)` | 这是人为设定的理想框，说明预测与目标可以相同；不是宣称网络自动给出了答案 |
| 示意分数 | 物体性 0.9、烟雾 0.2、火焰 0.8，火焰组合分数 `0.9×0.8=0.72` | 类别是独立 Sigmoid 分数，二者不要求和为 1；这是展示用分数 |
| 还原到原图 | xywh 为 `(530,220,50,25)`，角点回到原值 | 先去补边，再除缩放比例；说明舍入只发生在显示层 |

### 3.3 不把不同层次的数字混在一起

- 框恰好吻合的这个局部例子中，CIoU 为 1、框损失为 0；在当前标准设置下，该匹配位置物体性目标为 1，分数 0.9 的未加权 BCE 约 0.1054。
- 两类目标 `[0,1]`、预测分数 `[0.2,0.8]`，未平滑、未加权且对类别取平均的局部 BCE 约 0.2231。
- 这些不是整批训练的三项日志或总损失。还需计算其他位置、其他匹配、各尺度归约及权重；完整过程在损失课分步解释。
- 保留现有“给定 CIoU=0.6”的物体性交互，注明它是单独改变监督目标的局部实验，不能声称 0.6 来自上述完全重合的框。
- 保留当前更容易手算的中心 `(500,200)` 标签例子，作为标签课的入门预设；主线接续时明确切换到本节贯穿算例。
- 公交车实图是第二个迁移案例：原图尺寸、80 类、矩形/方形输入另行说明。它不能悄悄覆盖两类贯穿算例的条件。

## 4. 每课的讲述顺序与图文要求

每课组织为下述阅读过程，按实际需要合并小标题，不机械复制六个空标题：

1. **提出本课问题。** 例如：“已有 80×80 和 20×20 两张特征表，为什么还要让它们交换信息？”
2. **认识当前对象。** 用一小段解释名称、作用和输入输出；先说“把两组通道接在一起”，再引入 Concat API。
3. **把一个例子算完。** 图中标出来源、单位、运算和结果，正文解释每个变化。保留高宽不变、通道变化等“不变的量”。
4. **对应真实配置与代码。** 标出小例子如何对应标准网络；代码给运行位置、依赖和预期输出。只看本段即可识别示意代码还是可运行代码。
5. **处理一个典型误解。** 用具体反例说明哪里不成立，例如通道能相加，高宽却不匹配；说明失败原因。
6. **收尾并接下一课。** 写出已经得到什么对象、下一步要用它回答什么问题。总结使用本课得到的结论，避免重复“理解、掌握、提升能力”。

图解须有文字替代说明；用颜色区分来源时，同时显示层号、形状和名称。表格大于屏幕时只在表格容器内滚动，不能挤坏正文。交互不自动播放；键盘可操作，恢复默认后正文条件、图和数值一致。

| `yolo-sppf` / SPPF | 将汇总邻域的动机、小表池化、串联窗口范围、真实通道四件事依次讲完 | 复用池化交互，标明 1/5/9/13 是相对模块中间特征的范围；能算 512×4→2048→1024 |
| `yolo-neck` / FPN 与 PAN | 删除重复定义；先讲单次上采样/拼接/卷积，再走四条完整路径；解释高层、低层与图上方向 | 复用逐步连线；每次 Concat 同屏列两路来源；能解释层 19 为什么接层 14，而不是看到同尺寸就任接 |
| `yolo-head` / Detect 检测头 | 先两类 7 字段→21 通道→换轴→三尺度候选→训练/推理返回；项目改类与结构改造分组阅读 | 复用字段、换轴和改造组件；读者能从 `[1,21,80,80]` 解释到 `[1,3,80,80,7]`，再解释 `[1,25200,7]` |
| `anchors` / Anchor 与 AutoAnchor | 把参考宽高、预测框、真实框分开画；先说明为什么需要宽高参考，再讲匹配范围、统计和自动调整 | 固定一个网格，改变宽高参数；宽高比表与单位同步；知道 Anchor 不对应固定类别，BPR 不等于验证召回率 |

| `yolo-loss` / 三项检测损失 | 先列“谁被监督、目标是什么”，逐项代入公式；再处理负位置、跨尺度、gain 和 batch 缩放 | 框/物体性/类别分别高亮；贯穿局部例子和整批汇总分开；能解释负位置为何有物体性损失却没有框损失 |
| `train-yolo` / 训练循环 | 文件→一轮检查→一个 batch→一次更新→验证保存；术语在步骤中解释；示例日志逐列读 | 复用 batch/累积交互；给训练前后检查清单及带注释的假设日志；能区分 backward 与 step、batch 与 epoch |
| `yolo-checkpoints` / 权重与续训 | 用“首次初始化、换任务微调、意外中断恢复”三个场景区分；将输出头不兼容接到参数加载示例 | 文件字段/加载结果对照；能说明 `strict=False` 的边界，以及为什么 last 文件名不足以证明可以完整续训 |
| `yolo-augment` / 训练策略 | 一次讲清一种变换如何同时改图与框；再比较尺寸、batch 和实验预算 | 原图/变换图/变换框三联图；沿用训练算例；读者能识别框未随翻转改变的错误，并提出一个可对照实验 |

| `inference` / 推理与后处理 | 将原始字段、解码坐标、组合分数、NMS、原图还原组织为连续过程；新增贯穿预设，局部旧例单独标明 | 复用解码/NMS，逐行显示保留或删除理由；能从 0.72 追到两个分数，并还原原图框 |
| `yolo-export` / 导出部署 | 按“谁读取文件、输入是什么、返回什么、外部还做什么”解释导出；先复核输入和原始输出，再谈最终框 | PyTorch/目标后端逐阶段对照表；保留临界门槛例子；能定位差异发生在预处理、网络还是后处理 |
| `yolo-trace` / 实图串讲 | 保留公交车实图；开头列出与两类案例的差异，分基础通读和源码复查；避免重复灌入整套训练术语 | 同一照片各站串联，标清人工框与实际图像；读者能解释方图 25,200 与矩形 18,900 的差别 |

## 6. 优先做好的六组图文与交互

### 6.1 从一张图到逐层张量

复用 `textbook-yolov5l.js`、`textbook-yolo-workshops.js` 和既有 0～24 层数据。

- 每步同时呈现：当前层号、读取的来源层、输入形状、操作、输出形状、保留给哪条后续分支。
- 完整账本覆盖 Conv、C3、SPPF、Upsample、Concat、Detect，不能只列五次下采样。
- 默认两类、640 方图；完整标准结构浏览器中的 80 类原始配置需醒目标明对照条件，不让同一标题下混用结果。
- 练习：先隐藏下一层结果，由读者预测形状，再显示运算。无需新增答题存储系统。
- 反例：同为 40×40，不意味着任意层都能替换当前横向连接；形状可相容，网络语义也可能被改变。

### 6.2 C3、SPPF 与 Neck 的模块内部

复用现有分支、池化和四路线组件，按教学顺序补说明。

- C3：小输入→主路→短路→拼接→融合，逐一标出通道。示意小表用于追数，实际特征不伪装成可读的烟雾图片。
- SPPF：先用小表看一次最大池化，再看保持空间大小的三次串联；四路从哪里来、何时拼接清楚可见。
- Neck：先单独认识上采样与 Concat，再走 20→40→80→40→20；每一会合点都能点击查看两个来源。
- 观察任务给具体结果，例如“上采样后高宽变了，通道为何仍为 512？”避免只写“观察信息融合”。

### 6.3 检测头：数字怎样装成一条候选

复用 `textbook-detect-head.js` 与 `yd-head-*` 组件。

- 两类主线显示 `[tx,ty,tw,th,to,t_smoke,t_fire]`，先说明它们是原始数字，再显示解码后的含义。
- 按 Anchor 连续 7 个字段标记 21 个通道；选择一个位置时，在卷积输出和候选记录中同步高亮对应数字。
- 可见正文保留 `[10,11,20,21]` 的正确/错误换轴示例；直接 view 的错误与同一输入比较。
- 训练返回三尺度列表；普通推理返回解码结果及原始结果；后处理按图片返回可变行数的框。用三张小表分开，不把输出解释混成一个巨大公式。
- 80→2 类、P2、解耦内容保持独立的输入输出对照与检查步骤，详见任务 6。

### 6.4 一条标签怎样进入训练

复用标签、邻格、BCE 交互，以第 3 节算例接通。

- 原图/画布/网格分别有坐标轴与单位；当前跟踪的框用名称和颜色双重标记。
- 逐步展示 `[b,c,x,y,w,h]`、匹配 Anchor、`(b,a,gj,gi)` 和局部目标。更换行列次序时现场说明原因。
- 监督图将已匹配位置的框、类别和所有位置的物体性分开；没有匹配目标时另显示当前实现的行为。
- 用局部数值演算解释 BCE 和 CIoU，再走当前源码的整批汇总；不能把三种不同目的的权重放在一行带过。

### 6.5 从候选到原图上的最终框

复用当前解码、NMS、计数和验证表。

- 给定原始数字→Sigmoid→坐标解码→类别组合分数→筛选→NMS→逆 letterbox，逐步显示当前数量和坐标所属空间。
- 先用 4 个人工候选演练；读者可改变一个门槛，先预测谁会留下，再核对逐行原因。
- 清楚区分：匹配 Anchor 的宽高比例门槛、显示/筛选分数门槛、NMS IoU 门槛、评价匹配 IoU 门槛。
- 最终无框时仍展示前面有多少原始候选，定位首次变为空的步骤；不同类别重叠时比较按类与跨类 NMS。

### 6.6 能照着做的项目操作

- 训练：文件准备、命令参数、预期目录、检查哪些输出；日志为人工示意时写明，不填造真实实验成绩。
- 改类别：数据类别表→构建两类头→读取加载日志→前向检查→小范围训练验证，形成有先后的操作说明。
- 导出：先对齐同一输入，再逐项比较原始输出、解码和最终框；接近门槛的差异单独展示。
- 排错：每个案例只定位一个现象，例如“框整体向下偏移”，展示错在补边处理时的具体坐标差。
